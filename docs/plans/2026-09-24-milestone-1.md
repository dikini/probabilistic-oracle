# Milestone 1 Implementation Plan

> Execution workflow: use superpowers:executing-plans to implement this plan task by task.

**Goal:** Produce a reproducible measurement of a frozen model's proposition scores.

**Architecture:** A thin oracle adapter records model observations. Independent
algebra and benchmark modules compute derived values and evaluation reports.

**Tech Stack:** Proposed Python package, pytest, Hugging Face tokenizer/model,
and vLLM. Dependency versions await hardware and backend compatibility checks.

This is a proposed sequence, not an implemented API or authorization to download
models. Refine the backend-specific steps after selecting and inspecting the stack.

## 1. Establish the runtime

- Inspect GPU availability and memory; select one model and exact revision.
- Verify candidate-token log-probability support and prompt rendering in the
  selected vLLM version using primary documentation and a small integration probe.
- Create `pyproject.toml`, `src/probabilistic_oracle/__init__.py`, and
  `tests/test_import.py`; lock resolved dependencies and document installation.
- Run `python -m pytest tests/test_import.py -v` in the new environment.
- Record the selected stack and commit the package setup.

## 2. Implement exact algebra

Files: `src/probabilistic_oracle/algebra.py`, `tests/test_algebra.py`.

- Add failing tests for complements, conditional products, and Bayes updates.
  Reference case: prior 0.2, likelihoods 0.8 and 0.1 give posterior 2/3.
- Cover priors 0 and 1, zero evidence probability, out-of-range values, NaN,
  and infinities. Specify an explicit undefined-conditioning error.
- Run `python -m pytest tests/test_algebra.py -v`; confirm meaningful failures.
- Implement minimal functions, rerun the same tests, and commit on success.

## 3. Implement the oracle contract and adapter

Files: `src/probabilistic_oracle/oracle.py`,
`src/probabilistic_oracle/backends/vllm.py`, `tests/test_oracle.py`,
`tests/integration/test_vllm.py`.

- Specify request/result records and tests for stable normalization, missing
  candidate probabilities, invalid numbers, and incompatible verbalizers.
- Add tokenizer checks at the exact prompt boundary and preserve raw scores.
- Run `python -m pytest tests/test_oracle.py -v` before and after implementation.
- Implement the version-verified adapter. Keep fixtures clearly distinct from
  real inference records.
- Run an explicitly enabled integration smoke test on the selected model;
  inspect returned token IDs and log-probabilities. Record hardware and results.
- Commit the adapter and contract when their applicable checks pass.

## 4. Build benchmark cases and records

Files: `bench/cases/synthetic.json`, `bench/cases/world.json`,
`src/probabilistic_oracle/bench.py`, `tests/test_bench.py`.

- Define small finite synthetic worlds with exact reference probabilities.
- Add related queries for negation, conjunction, and the two Bayesian paths.
- Include paraphrases and irrelevant-context variants under stable case IDs.
- Write failing tests for exact targets, case-level split isolation, and run
  record round trips. Run `python -m pytest tests/test_bench.py -v`.
- Implement JSON records with prompt, model, tokenizer, code, settings, and error
  provenance. Rerun tests and commit the benchmark infrastructure.

## 5. Measure and report

Files: `src/probabilistic_oracle/metrics.py`,
`src/probabilistic_oracle/cli.py`, `tests/test_metrics.py`,
`tests/test_cli.py`, `docs/experiment-protocol.md`.

- Choose metrics, baselines, calibration fit/evaluation splits, and acceptance
  thresholds before the held-out evaluation; document them in the protocol.
- Test metric formulas against hand-calculated examples and test that missing
  observations are reported instead of silently discarded.
- Run `python -m pytest tests/test_metrics.py tests/test_cli.py -v` before and
  after implementing reporting and a small end-to-end fixture run.
- Provide separate raw and calibrated results, paraphrase/context sensitivity,
  complement and conjunction discrepancies, and Bayesian-path discrepancies.
- Run `python -m pytest` for GPU-free verification and the real backend check
  separately. Save real runs under ignored `runs/` and a compact evidence report
  under `docs/`, recording commands and limitations.
- Update README.md with the verified run commands and measured status; commit.
