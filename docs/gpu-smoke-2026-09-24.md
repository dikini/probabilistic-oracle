same GPU. Four sequential requests completed and returned finite raw
log-probabilities for both TRUE and FALSE. No out-of-memory error occurred.
Desktop responsiveness was not measured.

GPU monitoring sampled approximately every half second. These are observations
from one short run, not guarantees under changing GUI load. Used and free memory
do not sum to total memory because the driver also reserves memory. Request
timing includes returning and materializing full-vocabulary log-probabilities;
it is not a model throughput benchmark.

## Configuration

Model: [Qwen/Qwen3-0.6B](https://huggingface.co/Qwen/Qwen3-0.6B), pinned to
`c1899de289a04d12100db370d81485cdf75e47ca` for both model and tokenizer.

BF16 weights, context limit 512, one sequence, batched-token limit 512,
`gpu_memory_utilization=0.5`, eager execution, no prefix caching, seed 0.
Thinking is disabled through the chat template. Each request generates one
token with greedy decoding. The output distribution is explicitly configured
as `raw_logprobs`, before sampling transformations.

This vLLM release lacks selected-token log-probability requests. The probe asks
for the full vocabulary and extracts TRUE (20611) and FALSE (30351). Both are
single tokens and their tokenization was checked at each rendered prompt
boundary. Neither candidate is constrained or forced during generation.
The [versioned sampler source](https://github.com/vllm-project/vllm/blob/v0.11.2/vllm/v1/sample/sampler.py)
defines the raw log-probability behavior used here.

## Scores

These are normalized TRUE/FALSE plausibility scores, not calibrated probabilities.

| Case | TRUE score | Combined raw candidate probability mass |
| --- | ---: | ---: |
| Only red balls; drawn ball is red | 0.8670 | 0.9982 |
| Only red balls; drawn ball is not red | 0.1480 | 0.9960 |
| Fair coin; lands heads | 0.5927 | 0.9968 |
| Fair coin; does not land heads | 0.3208 | 0.9971 |

The coin scores sum to about 0.9135 rather than 1. This is an illustration of
the inconsistency the future benchmark will measure, not a conclusion about
the model from four cases. No calibration fit or held-out evaluation was run.

## Reproduction

From the repository root:

```bash
uv venv --python 3.12 .venv
uv pip sync --python .venv/bin/python requirements-smoke.lock
.venv/bin/python scripts/gpu_smoke.py
```

The environment snapshot targets this Linux NVIDIA setup. First execution can
download approximately 1.5 GB of model weights as well as several GB of runtime
dependencies. Weights use the Hugging Face cache, outside Git.

The script writes exact prompts, token IDs, scores, settings, package versions,
Git state, and GPU samples to ignored `runs/*-gpu-smoke.json` files. The original
local record is `runs/20260924T174554Z-gpu-smoke.json`, with the startup log in
`runs/gpu-smoke.log`. The probe was uncommitted when that run was captured, which
is reflected in its recorded Git state.

Verification: the script compiled, all four requests completed with finite
candidate scores, the process exited with code 0, and `uv pip check` reported
all 162 installed packages compatible. GPU usage returned to the GUI baseline.
vLLM emitted an NCCL process-group cleanup warning at exit; no GPU allocation
remained from the inference process in the post-exit check.

This script is an experimental hardware probe. The oracle API, probability
algebra, calibration protocol, and full benchmark remain to be implemented.
